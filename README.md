# Starmer Global — website

Website for **Starmer Global** (Lahore, Pakistan): complete production lines, machines,
dies and spare parts for hard candy, lollipop, chew & toffee, bubble gum and pharma
lozenges.

Live site: **https://www.starmerglobal.com**

---

## How the site is hosted

The site is plain HTML, CSS and JavaScript (no build step) hosted on **GitHub Pages**.

* Everything on the `main` branch of this repository is the live site.
* A push to `main` is live at www.starmerglobal.com within about 1–2 minutes.
* The domain is set by the `CNAME` file; `.nojekyll` tells GitHub to serve files as-is.

Because a push goes straight to the live site, **work on a separate branch and open a
pull request** for review before it is merged into `main` (see *Working on the site*).

| `product.html?id=…` | One machine, die or spare part (filled from the catalog) |

| `css/style.css` | All custom styles (Tailwind is loaded from its CDN) |
| `js/bundle.js` | All site behaviour |
| `js/catalog-data.js` | The catalog, loaded by every page (generated, see below) |
| `data/catalog.json` | The same catalog as JSON (generated, see below) |
| `assets/images/` | Category, gallery, line and page images |
| `assets/STARMER/_plated/` | Machine photos used by the catalog |
| `assets/videos/` | Home page hero videos |
| `booklet-data/` | Source data: one YAML file per production line (specs per machine) |
| `admin-local/`, `server.js` | Local admin panel for adding/editing machines and parts |
| `scripts/` | Build scripts (catalog, SEO, line header images) |
| `sitemap.xml`, `robots.txt` | For search engines (generated by `scripts/build_seo.py`) |
| `docs/SEO-GUIDE.md` | **Guide for SEO / marketing work** |

## Running it on your computer

Any static server works, for example:

```bash
python -m http.server 8099
```

Then open http://localhost:8099.

## The catalog (lines, machines, specs)

The machine data has one source of truth: the YAML files in `booklet-data/`.

1. Edit the line's file in `booklet-data/<category>/<line>.yaml`.
2. Rebuild the site data:

   ```bash
   python -m pip install pyyaml
   python scripts/templates_to_catalog.py --apply
   python scripts/build_seo.py
   ```

   This rewrites `data/catalog.json` and `js/catalog-data.js`, then refreshes the sitemap.

### Local admin panel

For quick edits there is a small admin panel (Node.js 18+):

```bash
npm install
npm run admin
```

Open http://localhost:3333/admin-local/ to add, edit or delete machines and parts and
upload photos. It writes straight to `data/catalog.json` and `js/catalog-data.js`;
commit those files afterwards.

> Changes made in the admin panel are **overwritten** the next time
> `templates_to_catalog.py --apply` is run from the YAML files. Use one method per change,
> or copy admin-panel changes back into the YAML.

The admin panel only works on your own computer (it needs `server.js`); the copy that
GitHub Pages publishes at `/admin-local/` does nothing and is hidden from search engines.

## SEO

Titles, descriptions, keywords, link previews, structured data, the sitemap and
robots.txt are all managed by **`scripts/build_seo.py`**. Line and machine pages build
theirs from the catalog automatically. See **[docs/SEO-GUIDE.md](docs/SEO-GUIDE.md)**.

## Working on the site (collaborators)

1. Create a branch: `git checkout -b seo/home-page-keywords`
2. Make the change and check it locally.
3. Commit, push the branch and open a **pull request** on GitHub.
4. After review it is merged into `main` and goes live automatically.

Please do not commit large source files (raw photos, PDFs, scans, video originals);
`.gitignore` already keeps the known ones out.
